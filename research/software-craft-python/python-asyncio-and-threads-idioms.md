# Research note — Python asyncio and threads idioms

Topic `python-asyncio-and-threads-idioms` of group python, domain `errors`, id prefix `PY`. Formulation locators: Ruff ASYNC, RUF006, PLE; CPython asyncio docs; the concurrency-correctness boundary.

The catalogs check Python's async and threading idioms mechanically: Ruff's flake8-async family (ASYNC100 timeout scope without a checkpoint, ASYNC105 un-awaited trio call, ASYNC109 timeout parameter, ASYNC110 sleep-polling loop, ASYNC119 yield inside a context manager in an async generator, ASYNC210 to ASYNC251 blocking calls in async functions), RUF006 dangling task, RUF029 unused async, B039 mutable ContextVar default, PLW2101 lock created in with, PLW1509 preexec_fn; SonarSource python S7483 to S7515 restate most of these and add cancellation re-raise (S7497), control flow inside a TaskGroup (S7514), single-task TaskGroup (S7513) and with on an async context manager (S7515); Pylint W2101 and W1509 match the two threading rules. The CPython documentation states the semantics behind the strongest of them: the event loop keeps only weak references to tasks (asyncio-task, Creating tasks), simply calling a coroutine does not schedule it (Coroutines; asyncio-dev, Detect never-awaited coroutines), blocking code delays every task (asyncio-dev, Running Blocking Code), a caught CancelledError should generally be propagated because TaskGroup and timeout are built on cancellation (Task cancellation), a ContextVar's default is what get() returns when the context has no value (contextvars), preexec_fn is not safe in the presence of threads (subprocess), and aclosing gives async generators deterministic cleanup (contextlib, PEP 533). Positions differ in three places: Ruff calls its timeout-parameter rule highly opinionated while Sonar states it as a plain rule; RUF029 and Sonar S7503 both exempt a function that must stay a coroutine for an interface or framework; and the subprocess documentation makes the preexec_fn deadlock conditional on threads while Ruff flags every preexec_fn. Ten rules are carded; five checkable rules are held at the cap and three candidates fold into them. No candidate covered asyncio.run placement or gather against TaskGroup, which the topic owns, so those stay uncovered by this run.
