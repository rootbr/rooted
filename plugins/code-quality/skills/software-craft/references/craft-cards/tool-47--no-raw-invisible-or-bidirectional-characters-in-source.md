# Source text a change adds holds no raw bidirectional control, invisible format character or control character other than tab and line endings in its code or literals, writes any that a literal needs as an escape sequence, and holds a bidirectional embedding, override or isolate in a comment only when the same comment terminates it

## Thesis
Code and string or character literals that a change adds carry no raw bidirectional control (the embeddings, overrides and isolates U+202A to U+202E and U+2066 to U+2069, and the right-to-left and Arabic letter marks U+200F and U+061C), no raw invisible format character (a zero-width space U+200B, a soft hyphen U+00AD, a Mongolian vowel separator U+180E, a word joiner U+2060, or a byte order mark U+FEFF after the start of the file), and no raw control character other than tab and the file's line ending; a literal that needs such a character writes it as the language's escape sequence in a literal form that decodes escapes, so a raw literal that holds one becomes an ordinary literal. A comment that a change adds closes each bidirectional embedding, override or isolate it opens before the comment ends (an embedding or override by a pop directional formatting U+202C met while it is the innermost open control, an isolate by a pop directional isolate U+2069, which also closes every embedding or override opened inside the isolate) and carries no invisible format character and no control character other than tab and the line ending.

## Rationale
An embedding, override or isolate is invisible but reorders all the text after it until a dedicated character ends it or, in most editors, the line ends, so source that holds one can appear different to a compiler and to the human eye: a crafted comment can make code that will be compiled appear to be part of the comment, and a crafted literal can make the surrounding code seem to perform one action while it performs another. A directional mark is invisible and affects text as a right-to-left or left-to-right letter would, so a line that assigns a 200-character string, half of it right-to-left marks, can render as the assignment of a one-character string followed by a comment. An invisible character can divide a multiline comment's terminating sequence, so a compiler typically does not close the comment and the lines after it do not run, and raw control characters are displayed differently by different text editors and terminals. An escape sequence in place of the raw character leaves a literal that decodes escapes holding the same value while it renders visibly in every editor (a raw literal keeps an escape as backslash text), and the check is a scan for code points that a build pipeline can run before each build. Where one language's package registry was analysed across every version ever published, 5 packages held one of the nine embedding, override, isolate or terminator code points in their source code, and none of the occurrences was malicious.

## Example
```python
bad:  label = "⁦user⁩"   # raw U+2066 and U+2069 around user
      joined = "a​b"     # raw U+200B between a and b
good: label = "\U00002066user\U00002069"
      joined = "a\U0000200bb"
```

## Limits
A printable non-ASCII character stays literal, since an escape for a printable character obscures it, and the left-to-right mark U+200E, the default for Latin-script files, cannot be used to hide code and is outside the rule. The rule does not reach a byte order mark at the file's first character, which the file's encoding convention governs, and a form feed that separates pages of related sections is outside the rule where the language's style guide accepts it as whitespace, although some editors and viewers show another glyph in its place. Where a bidirectional control sits separates the positions on it. One position rejects every raw embedding, override or isolate in comments and literals alike, replaces a legitimate one by its escape sequence and judges that ban may well be sufficient in most settings; compilers and linters that deny these characters by default, with no way to disable the check in one of them, hold it. The other bans only unterminated ones, because a full ban penalizes users with legitimate uses in comments and, once each control has its terminator, legitimate source outside literals and comments cannot be distorted; a compiler warning whose default level reports improperly terminated contexts and a linter check for unterminated sequences hold it, and a scan of public commits for unterminated controls in comments and strings found 98.8% of its results to be false positives, among them malformed strings in genuinely right-to-left languages and bidirectional characters placed into localized format string patterns, a figure the study does not take to predict a high false-positive rate for such a scan in practice. In code and literals a legitimate use keeps its value through the escape sequence, which renders visibly, so every raw control there is replaced as the first position asks; the penalty of a full ban falls on legitimate uses in comments, so in a comment only an unterminated embedding, override or isolate is flagged as the second asks, and a directional mark, which the research does not list among the characters relevant to reordering attacks, is not flagged there. A third position holds that the issues generally cannot be solved in the language itself without excessive restrictions and should be solved in code editors, review tools and project-specific policies, while confining these characters to strings and comments does not render them harmless, which places enforcement in review rather than disputing the hazard; one language's maintainers likewise called the attack an issue for code editors rather than for the language. A linter that restricts Unicode escapes flags the escape for a control character too unless it is configured to allow it, and the configuration published for the style guide that asks for escapes allows them. Where a language translates escape sequences before it lexes, an escape written outside a literal is decoded first, so an escaped line terminator in a comment ends the comment and the text after it executes; there an invisible or control character is removed from the comment rather than escaped.

## Validator
Grep the added lines of the hunk for the trigger code points: an embedding, override, isolate or directional mark (U+202A to U+202E, U+2066 to U+2069, U+200F, U+061C), an invisible format character (U+200B, U+00AD, U+180E, U+2060, U+FEFF), a control character (U+0000 to U+001F, U+007F to U+009F) other than tab, line feed and carriage return, and a carriage return not followed by a line feed. Set aside a byte order mark at the file's first byte, the left-to-right mark U+200E and a form feed used as a page separator where the style guide accepts one. For each remaining hit, decide from the hunk whether it sits in code, inside a string or character literal, or inside a comment. In code or a literal every hit counts. In a comment, an invisible format or control character counts; for the embeddings, overrides and isolates walk the comment with a stack of open controls, pushing each opener, letting a U+202C close the innermost open control only when that control is an embedding or override, letting a U+2069 close the innermost open isolate together with every embedding or override opened after it and ignoring a terminator that matches nothing, and count each opener still open at the comment's end; a directional mark in a comment does not count. Validator question: **Does an added line hold, in code or a literal, a raw bidirectional control, invisible format character or control character other than tab and the line ending, or, in a comment, an invisible format or control character or an embedding, override or isolate that the same comment leaves unterminated?** Yes → flag.

## Finding output
When the validator answers yes, the finder emits one finding (`rule_id: TOOL-47`, severity major, `file`, `symbol`, `code` = the added line holding the character, with its code point named as U+XXXX because it does not render, `fix` = the same line in the file's language with the character written as the language's escape sequence inside a literal, a raw literal rewritten as an ordinary one so the escape is decoded, removed from code or from a comment, or with the missing terminator added inside the comment, `rationale` = the code point, whether it sits in code, a literal or a comment, and how it lets the line display differently from what the compiler reads).
