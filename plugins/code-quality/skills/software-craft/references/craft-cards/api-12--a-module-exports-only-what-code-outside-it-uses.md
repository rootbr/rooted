# A module exports only what code outside it uses or what its documentation presents as its API, and keeps every other member non-public

## Thesis
Each name that a change adds to a module's exported or public surface (a type, an interface, a function, a method, a field or a constant of a package, a file module or a class) is one that code outside the module uses, or one that the module's documentation presents as part of its API. A name used only inside its module stays non-public. A name whose place in the API is in doubt starts non-public. Where the language marks a non-public name by a naming convention rather than by enforced visibility, the name carries that mark, even where the module also declares the list of its public names.

## Rationale
A public name is one that unrelated callers are expected to use, and making it public commits the module to maintaining it for them and to avoiding backward-incompatible changes to it. A non-public name carries no such guarantee: it may change or even be removed, so a module that hides its implementation details lets its author know which parts of its code can change without breaking the code outside. The two directions are not equally easy: a non-public name is easier to make public later than a public name is to make non-public, which is why a name in doubt starts non-public. Compatibility guarantees apply only to the public surface, so callers need to be able to tell the public names from the internal ones. A private marking on a member declares to human readers and to automated tools that the member is accessed only inside its declaring type, and both rely on that: a check for unused code flags a private member that appears unused. Every exported type also adds to the cognitive load of the module's readers, and a module's exported surface is generally kept to a minimum.

## Example
```python
bad:  __all__ = ["load_config", "parse_line"]
      def load_config(path):
          with open(path) as f: return [parse_line(x) for x in f]
      def parse_line(line): ...
good: __all__ = ["load_config"]
      def load_config(path):
          with open(path) as f: return [_parse_line(x) for x in f]
      def _parse_line(line): ...
```

## Limits
A member used from outside the lexical scope of its declaring type, such as from a template, is used outside that scope and is not made private. A name that a test runner, a serializer or another framework finds by its name or by reflection, and can reach only while the name is public, is used outside its module too, though no code in the repository names it: a test function or test method the runner discovers by its name, a field a serializer reads or writes. A type that the signature of a public name carries, as a parameter, result or public field type, belongs to the API with that name, though callers that pass or receive its values never name it; made non-public, it leaves them unable to declare or document those values and, where type privacy is enforced, unable to use them. A name that unrelated callers are meant to use is part of the API though nothing in the repository calls it: a name the module's documentation presents, and a submodule's name that a package's entry module exposes as an explicitly documented part of the package's API. Likewise, a package whose product is an interface, a common protocol that many different implementations must follow, may export that interface. A class designed to be inherited from may give its subclasses a subclass API beside its public and its non-public members, where its design decides explicitly which members belong to each. A use by tests does not justify exporting, solely for testing, a back door into the module or a test double of an interface the module consumes; tests preferably go through the public API of the real implementation. The rule reaches a name that the change adds to the public surface or makes public. A name that is already public stays public under this rule, since making it public committed its module to maintaining it for external callers, and withdrawing it is a change of its own.

## Validator
In the hunk, list each name the added lines put on a module's public surface: a declaration the language exports or marks public, a member declared without a modifier where the language's default visibility is public, a name added to the module's declared list of public names, and, where the language marks non-public names by a naming convention, a module-level or member name that lacks the mark. Skip a local name declared inside a routine body, a name that an import statement binds unless the added lines also export it or put it on the module's declared list of public names, and a name that the hunk's removed lines show was already public. For each remaining name, search the repository for its uses outside the module that declares it: imports and calls from other files and packages, calls through an interface or a base type that the name implements, uses from templates or other files outside the declaring type's code, and the name's place as a parameter, result or public field type in the signature of another name that stays public, which every caller of that name reaches without naming the type. A test runner, a serializer or another framework that finds the name by its name or by reflection, and reaches it only while it is public, also counts as a use outside the module: a test function or test method named by the runner's convention, a field a serializer reads or writes. Do not count a use from a test file in which the name serves only as a back door into the module or as a test double. Read the module's documentation, its package entry module and the project context for the name. A doc comment on the name's own declaration presents the name as part of the API only where the module is published for callers outside the repository, such as a library's public package; elsewhere it does not, since a style may require a doc comment on every exported name. Skip a name that the documentation or the project context presents as part of the API, a name the package's entry module exposes as documented API, an interface that is the package's product for many implementations to follow, and a member that a class designed for inheritance explicitly gives its subclasses. Validator question: **Does the change put on a module's public surface a name that no code outside the module uses and that neither the module's documentation nor the project context presents as part of its API?** Yes → flag.

## Finding output
When the validator answers yes, the finder emits one finding (`rule_id: API-12`, severity minor, `file`, `symbol`, `code` = the added declaration, export statement or public-list entry that puts the name on the public surface, quoted verbatim from the diff, `fix` = that declaration made non-public by the language's own means, either with the export or public modifier removed or narrowed to the smallest visibility that covers the name's uses or with the non-public naming mark added and the name taken off the module's declared list of public names, in the file's language, `rationale` = where the name's uses were found, all inside its module, and the commitment to callers outside the module that a public name carries).
