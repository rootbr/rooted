# Gotchas — software-craft

Symptom → cause → fix for the card-dispatched build and review, each tied to the file that owns the behaviour. Cold-tier reference: read when a run misfires — a shallow report, a finding that verification should have rejected, a workflow that dies on its first agent, a card that never triggers, a developer agent that edits outside its zone. Stable IDs: a retired entry keeps its number vacant rather than reusing it (house convention). Pointer in `SKILL.md` §Gotchas.

Paths are relative to the skill directory; `craft/…` and `.claude/…` are in the repository under review.

G-01. Finders produce shallow, generic findings, and the same diff reads as style in one repo and correctness in another? The pre-pass found no `.claude/software-craft/config.md`, so every finder prompt carries "(no project context was given)". Ask the author for the project's invariants and tolerances and write them into `config.md` before re-running the pre-pass; a review without them cannot reject a finding on a documented tolerance, and cannot run a single `PROJ-N` card.

G-02. A skeptic confirms a finding the surrounding code plainly handles? It read the finding's quoted snippet and stopped. The skeptic prompt (`scripts/craft-review-workflow.js`, `skepticPrompt`) requires opening the whole enclosing routine at head and the diff of the file; a verdict whose `evidence` names neither is a verdict to distrust. Re-run that finding's verification by hand with the same prompt.

G-03. A finder returned an empty array: the run is fine. "No findings" is the expected outcome for most (card by slice) jobs — a card triggers on a lexical net or a signal threshold far wider than its defect. The empty result is data; a quiet finder is left alone.

G-04. A finding's location no longer matches after a rebase or a follow-up edit? Findings anchor by `file` + `symbol` (the enclosing routine or type in the file's own notation) + the verbatim `code` fragment, and by nothing else; the render script prints the symbol, and the skeptic re-anchors by the fragment. A finding that carries only a line number came from a prompt that was edited — restore the `symbol` requirement.

G-05. A finding with no anchor in the diff? Speculation. The finder discipline (`plugins/code-quality/agents/craft-finder.md`) and the skeptic's false-positive check both require the quoted `code` to be an added line of the diff; a skeptic that cannot find it rejects the finding, and "conceptually similar to existing issues" is not an anchor.

G-06. A resumed verify stage rejects findings as "not in the diff", or confirms code that has since changed? The checkpoint `craft/findings.json` carries the pre-pass inventory with `base_sha` and `head_sha`. If the tree moved after the find stage — a committed head advanced, or the working tree was edited — the findings describe code that no longer exists: re-run the pre-pass and the find stage rather than verifying stale findings against a new tree.

G-07. Logic-pass slices cut across a module, or one slice holds an unrelated mix? The pre-pass groups files by the directory one segment below the changed files' common root, which assumes directory ≈ module, and slices test files apart. Where logical modules span directories, name them in `config.md` frontmatter — `modules: [{name, paths: [..]}]` — and the pre-pass slices by module instead.

G-08. The workflow dies on its first agent with "agent type 'code-quality:craft-finder' not found"? The three agent types are declared by this plugin and resolve only where the plugin is installed, as `code-quality:craft-finder`, `code-quality:craft-verifier` and `code-quality:software-developer`. In a repository checkout, or any session that lists only the built-in types, omit `agentTypes` from the bundle and run the developer definition's body as a general-purpose agent's prompt: every prompt carries the read-only prohibition and the injection stance, and the integrity check after the run is the backstop.

G-09. A file under the repository changed during the review beyond the diff under review? The dynamic-workflow runtime grants `Write`/`Edit` to sub-agents regardless of their `tools:` allowlist (claude-code#63762), so inside a run the prompt's prohibition is the only barrier. Treat a mutated tree as a compromised review: discard the findings, restore the tree, and re-run through the Agent-tool fallback, which does enforce the allowlist. In a worktree review the integrity check compares `git status` and `git diff --stat` against the developer agent's reported changes, since the tree is dirty by design.

G-10. The audit of a card flags a "backslash path" in its frontmatter? A trigger written as `catch\s*\(` reads as a Windows path to the audit's static pre-pass. Write the keyword family with word boundaries — `\b(catch|except|rescue)\b` — and a literal dot as `[.]`, which the card validator enforces; the patterns match the same text.

G-11. `node --check` rejects a workflow script with "Illegal return statement"? The workflow runtime wraps the script body in an async function, so the script's top-level `return` is legal there and illegal in a bare module. Check the syntax as the runtime sees it: wrap the file in `async function __workflow(args, agent, parallel, pipeline, phase, log, budget, workflow) { … }` in a temporary copy, with the `export` keyword removed, and run `node --check` on the copy; `scripts/tests/test_bundle_run.py` does this for both workflow scripts.

G-12. Finders search files the plan never matched, or a card's trigger list looks truncated in the run? The plan was retyped into the tool call by hand. Bundle it instead: `scripts/bundle-run.py` writes `craft/run.js` with the plan embedded verbatim from `craft/plan.json`, and the Workflow call names that script with no `args`; `root` in the bundle is the absolute repository path.

G-13. A control that a documented tolerance covers still reaches the report? The tolerance sits in a code comment the skeptic never opened, or in `project_context` phrased so that no card's Limits recognise it. Tolerances that reject a finding are stated in `config.md` in the vocabulary of the card's Limits, and the fixture's controls are the regression tests for that path.

G-14. A signal card never triggers on a defect you can see? The pre-pass measured the signal below its threshold, or the routine detector did not recognise the enclosing routine's signature in that language. Read `craft/plan.json` — each hunk carries its measured `signals` — and compare with the design note's threshold; a signature shape the detector misses is a `scripts/static-craft.py` change with a test in `scripts/tests/test_static_craft.py` for that language.

G-15. The pre-pass reviews nothing although the developer agent reports changes? The changes are in files the deny-list skips — a vendored tree, a generated file, an unknown extension — or the agent ran the pre-pass with a `--diff-ref` in a working-tree session. `craft/plan.log` names every skipped file with its reason; run without `--diff-ref` for an uncommitted diff, and new files count as wholly added (the pre-pass lists untracked files itself and stages nothing).

G-16. A research topic's cards cite a paper the skeptic could not open? The authoring environment reaches papers only through the search index, so a paper enters a card as `relayed` with the snippet quoted on the provenance line. A card whose only anchor is `unfetched` never ships; re-verify `relayed` citations from an environment with arXiv access and mark them `fetched` on the provenance line when the paper states the claim.

G-17. The developer agent edited files outside the write zone, or ran `git commit`? Its definition forbids both, but a task that names no zone leaves the agent to infer one from the task's subject. Name the write zone in the task text, and treat a version-control write as a compromised build: reset the commit, keep the tree, and re-run the review on the working tree.
