# A type written as a singleton offers no second way to obtain an instance, so no constructor, copy or deserialization reachable from outside it yields a new object

## Thesis
A type written to have exactly one instance, which code obtains through an accessor, a static field or a package-level value, offers code outside its defining class, module or package no route of its own to any other instance. Its constructor, any factory other than the accessor and its literal form are private to the definition, so outside code can neither call them nor reach them through a subclass, or the call returns the existing instance; in a language whose privacy is a naming convention, private means carrying the convention's internal-use mark. It offers no copy or clone operation that returns a new object: the operation is absent, refuses, or returns the existing instance. It is not serializable, or, where a serialized form is indispensable, that form is only a name that deserialization resolves to the existing instance, never the state from which a new object is built. A construct the language itself keeps to one instance meets the rule directly: an enumeration with a single constant, where the platform refuses to clone enumeration constants and deserializes them by looking up their name, and a module that holds the shared state in module-level variables rather than in an instance of a type, which the runtime loads once and shares with every importer. A once-only initialiser makes the accessor build its instance once and closes none of the other routes; the type closes them itself, by its visibility and by the copy and serialization it declines to offer.

## Rationale
Code that uses a singleton relies on there being one instance: its instance fields occur only once, just like static fields, and a singleton often controls access to a resource such as a database connection or a socket. Each open route makes multiple instantiation possible, violating the singleton pattern and the expected contract of the type: a constructor visible outside the definition, including a default constructor the language supplies when the type declares none; a protected constructor, whose access a subclass can widen so that untrusted code creates instances; a clone; and deserialization, which can bypass the constructor, so a check placed in the constructor cannot enforce a single instantiation. A hook that substitutes the existing instance once deserialization has built a new object does not close that route: a field of the stream is deserialized before the hook runs, so a crafted stream can capture a reference to the new object, even when every field of the type is excluded from serialization. Where the platform refuses to clone an enumeration constant and deserializes it by its name alone, without its field values, a single-constant enumeration closes both routes and ensures that only one instance exists at any instant.

## Example
```go
bad:  type Registry struct{ entries map[string]int } // &Registry{} compiles in any package
      var Instance = sync.OnceValue(func() *Registry {
          return &Registry{entries: map[string]int{}}
      })
good: type Registry interface{ Lookup(key string) int }
      type registry struct{ entries map[string]int }
      func (r *registry) Lookup(key string) int { return r.entries[key] }
      var Instance = sync.OnceValue(func() Registry {
          return &registry{entries: map[string]int{}}
      })
```

## Limits
Code inside the definition keeps the constructor: a private constructor bars instantiation outside the class body only, so the rule reads the routes left open to other code. A type that callers are meant to construct, and that also offers a shared default instance for convenience, is not written to have only one instance, and the rule does not reach it. A module-level instance is single per loaded module, not per process: a runtime that caches modules by resolved filename returns a different object when the same name resolves to another file, and on a case-insensitive file system reloads a file reached under a differently cased name; a runtime that caches modules by URL loads a module again for an import with a different query or fragment; and a type loaded through a second class loader has an instance of its own, technically a different, independent type. Those copies come from how the program loads code, and an instance built by reflection or by a cast that skips the type check comes from bypassing the type's visibility; neither is a route the type offers, and the rule does not reach them. Whether lazy initialisation stays single under concurrent first calls, whether an accessor that builds a new object on every call keeps the pattern, and whether the program should hold a singleton at all are outside the rule.


Module-level variables meet this rule only for state that no otherwise independent components change or observe; moving such shared state into module-level values is no fix this rule offers, and that state is judged by its own rule.
## Validator
Grep the added lines for the marks of a singleton — an instance accessor, a static or package-level field that holds the instance, a once-only initialiser — and for the routes that copy or rebuild an object: a serializable or cloneable marker, a derived clone, copy, default or deserialize implementation, a copy or reduce hook, a public constructor. Open the file and decide whether the type is written to have exactly one instance: its accessor returns one stored instance, its documentation or name says it is the only one, or a once-only initialiser builds it; pass a type that callers are meant to construct. For a singleton type, list every route other than the accessor by which code outside its class, module or package can obtain an instance: a constructor, factory or literal form visible outside the definition, including the default constructor supplied when the type declares none, a protected constructor, a derived default, and, where privacy is a naming convention, a type or constructor name without the internal-use mark; a copy or clone operation that returns a new object; a serializable marker, derived deserializer or deserialization hook that builds a new object from the stream, including one whose resolve hook substitutes the existing instance afterwards; and a copy or serialization the language applies by default to any value whose type does not override it. Pass a constructor or factory call that returns the existing instance, a single-constant enumeration on a platform that refuses to clone enumeration constants and deserializes them by name, a module whose shared state lives in module-level variables rather than in an instance of a type, and a copy or deserialization that refuses or returns the existing instance by name. Validator question: **Does a type written to have exactly one instance leave code outside its definition a route other than its accessor — a visible constructor, factory or literal, a copy or clone that returns a new object, or a deserialization that builds a new object — by which a second instance can be obtained?** Yes → flag.
