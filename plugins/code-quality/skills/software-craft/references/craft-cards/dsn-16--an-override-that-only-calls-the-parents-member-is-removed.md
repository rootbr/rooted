# An override or constructor whose whole body calls the parent's same member with the same arguments is removed, unless it changes visibility, modifiers, annotations, defaults or the signature callers see

## Thesis
An overriding method whose whole body is one call to the parent's method of the same name, passing the method's own parameters in declared order and unchanged and returning the call's result unless the parent's method returns nothing, is removed, so that callers reach the inherited method directly. Two more shapes follow the same rule: a constructor that is the only one its class declares and whose whole body passes its own parameters unchanged to the parent's constructor, where a class that declares no constructor receives one that delegates to the parent's; and a method whose whole body calls the same method, with the same arguments, on a field embedded in its type, where embedding already promotes that method to the receiver the forward declares. The member stays when it changes something its call does not show: a visibility different from the parent's member or, for a constructor, from the constructor the class receives when it declares none, or a constructor marked non-public, or a visibility that admits subclasses and the declaring package's code but not all code, redeclared in a package other than the parent's; a final declaration; a modifier that adds behaviour to the call, such as holding a lock while it runs; an annotation or decorator on the member or on one of its parameters, other than the marker that declares an override or one that suppresses a warning; a parameter that also declares a field; a default value, parameter list, parameter type, return type or declared exception list different from the parent's member or, for a constructor, from the constructor the class receives when it declares none; a parent member declared abstract, which the class must override to be instantiated; a call qualified to pick one of two inherited implementations of the member; or a forward declared on the outer value to a method that a field embedded by value defines on a reference to itself, which embedding promotes only to a reference to the outer type.

## Rationale
Such a member does the same thing as the member it forwards to: removing it does not change how the class works, because the inherited member then takes the call, and a method that embedding promotes to the forward's receiver has exactly the same effect as a forwarding method written out by hand. Kept, it is useless and misleading, a declared member that performs no action beyond the call, and for an embedded field the forwarding is bookkeeping that embedding already does. One tool that ships the check rates it a minor maintainability issue with a constant remediation cost of two minutes for removing the member. The rule restores the property that an override does more than call the same member of its parent. Each exemption is a change the member makes without showing it in the call: a final declaration locks in the parent's behaviour; a modifier such as synchronization adds behaviour; adding a decorator changes behaviour; a different visibility makes the member visible where the parent's is not, and a constructor marked non-public restricts who may construct the class; the constructor a class receives when it declares none exists only while the class declares no other, and it can differ from the parent's in visibility and declared exceptions; a different default value, parameter list or return type changes the signature callers see; a bare call drops a result the parent's member returns, and removing it hands that result to callers; a qualified call can be disambiguating between inherited implementations; and a class cannot be instantiated until it overrides every member its parent declares abstract, even with an override that only calls the parent's implementation; and a field embedded by value gives the outer value only the methods it defines on itself, so a forward on the outer value is what gives it a method the field defines on a reference to itself.

## Example
```typescript
bad:  class Report extends Page {
        constructor(title: string) { super(title); }
        override render(format: string): string { return super.render(format); }
      }
      new Report("summary").render("pdf");
good: class Report extends Page {}
      new Report("summary").render("pdf");
```

## Limits
Overrides of the equality, hashing and text-representation members are skipped by one tool that ships the check, the copy member by another, and the hashing member next to an overridden equality by a third, and the rule skips all four: an override of the hashing member next to an overridden equality is meaningful even when trivial, and a copy member is considered good practice to implement anyway. One tool also skips every such member in a class that carries a transaction annotation. Where the constructor a class receives when it declares none does not pass its arguments to the parent's constructor, a constructor that does is how callers construct the class with those arguments, and the rule does not reach it. A method that forwards to a field that is not embedded is how the type provides that field's method, and it stays; whether to embed the field instead is a design choice the rule leaves open. Where two embedded fields at the same depth provide a method of the same name, the name is ambiguous, and a forwarding method on the outer type, which hides both, picks one of them; it stays. A language with no implementation inheritance between types, in which an override cannot call the default implementation it replaces, has no instance of the pattern. When the parent's declaration lies outside the file, the file cannot show a parent member or constructor that admits fewer callers than the forward does — a forward declared without a visibility keyword admits all code in a language whose members default to that, and a forward marked to admit all code may override a member that admits only subclasses — nor a result that a bare call drops; such a forward changes what callers see and stays, so a finding raised from the member alone names what it assumed of the parent's declaration. A tolerance stated in the project context for such members rejects the finding.

## Validator
Grep the added lines for a member call on the parent, a call of the parent's constructor, and a call of a method through a field of the receiver. Open the file and find the member that encloses the match. Check that its body is a return of that one call, or the bare call where the parent's member returns nothing, and nothing else; that the call names the member's own name on the unqualified parent, the parent's constructor, or the same method on a field embedded in the type, other than a forward declared on the outer value to a method that the field, embedded by value, defines on a reference to itself; and that its arguments are the member's own parameters in declared order and unchanged, or a spread of all of them. For a constructor, confirm that the class declares no other constructor, and that a class declaring none would receive one that delegates to the parent's with this constructor's visibility and declared exceptions. Then compare the member with the parent's declaration when the file holds it: whether the parent declares the member abstract, visibility, modifiers, annotations and decorators on the member and its parameters, parameters that declare fields, default values, the parameter list, parameter types and return type, and whether the parent's member returns a result that a bare call drops. When the file does not hold the parent's declaration, judge from the member alone: an explicit visibility keyword on a constructor, any default value, any parameter decorator and any parameter that declares a field each clear it, and a method's visibility and types are taken to match the parent's, except that a method whose visibility admits subclasses and its own package's code but not all code clears it when its class extends a parent declared in another package. Skip equality, hashing, text-representation and copy members, overrides of a member the parent declares abstract, members of a class that carries a transaction annotation, a call qualified to pick one of two inherited implementations, and a forward to a field that is not embedded. Validator question: **Is the added member an override, its class's only constructor or an embedded-field forward whose whole body calls the parent's same member with its own parameters unchanged and returns its result unless that member returns nothing, while changing none of visibility, modifiers, annotations, decorators, default values, declared exceptions or the signature callers see?** Yes → flag.

## Finding output
When the validator answers yes, the finder emits one finding (`rule_id: DSN-16`, severity minor, `file`, `symbol`, `code` = the added declaration line of the member and its forwarding call, verbatim from the diff, `fix` = the class or type with the member deleted and callers reaching the inherited or promoted member, in the file's language, `rationale` = which inherited or promoted member already serves the call, that the forward changes nothing the call does not show, and, when the parent's declaration is outside the file, the visibility and result it assumed for the parent's member).
