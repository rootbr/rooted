# A schema, type, enumeration or interface needed in several forms is declared once, and every other form is derived, generated or imported from that declaration

## Thesis
A structure that the code needs in more than one form, each form having to change whenever the structure changes, is declared once, and every other form is derived from that declaration, generated from it, or, where the form is identical, imported from it. The forms in reach are a data or message schema used by several languages or services; a type's field list restated in its constructor, equality, hashing and printing methods; an enumeration's constants restated as their names or as a separate type; a type restated by hand as a variant of another type; and one interface declared identically in many modules. A form is derived by the language's own feature (a data-class or record declaration, a derive attribute, a type computed from another type or from a declared value) or generated by a tool run on a neutral specification (an interface-definition file, an API specification, database queries). A generated file carries, before its first line of code, a marker that tells humans and tools it is generated and not to be edited by hand.

## Rationale
A hand-written method that maps an enumeration's constants to their names has to be maintained whenever the set of constants changes and checked for correctness, and two names for one value make that harder; a generator rerun after the definition changes updates the method, and every such method in the package, with a single command. Information kept redundantly across artifacts is often incomplete or inconsistent in practice: projects capture the same specification in source code, tests and documentation, and in an evaluation of 835 specifications of the exceptions one library's methods throw, 85% were not tested or correctly documented, while generation from shared test and documentation templates could produce 97% of the tests and documentation. Each of the following mechanisms holds the structure in one declaration and produces its other forms. An interface-definition file defines how the data is structured once, and generated code writes and reads that data in a variety of languages; an API specification yields client libraries, server stubs and documentation; database queries yield code with type-safe interfaces to them. A record's equality, hash code and string form are derived from all of its component fields; a data-class decorator generates the constructor and printing methods from the annotated fields; a derive attribute generates an implementation of a trait with its default behaviour for the annotated type; a type can be based on another type, or on a value already declared, so that its members are written once. Identical interfaces declared in numerous modules of a large codebase make maintenance difficult and can create an unnecessary burden. A generated file is regenerated from its source after each change rather than edited by hand, and its marker tells humans and tools which files those are.

## Example
```typescript
bad:  const SIZES = ["small", "large"];
      type Size = "small" | "large";
      interface Item { id: string; size: Size }
      interface ItemPatch { id?: string; size?: Size }
good: const SIZES = ["small", "large"] as const;
      type Size = (typeof SIZES)[number];
      interface Item { id: string; size: Size }
      type ItemPatch = Partial<Item>;
```

## Limits
A form with no sensible default cannot be derived and is written by hand: a display format for end users is one, since which parts of a value an end user should see is a choice the compiler cannot make for the author. Where neither the language nor an available tool can derive or generate a form, the hand-written form is outside the rule. A hand-written member whose behaviour deliberately differs from the derived one is its own form, not a copy: a constructor that validates its arguments, makes defensive copies of mutable fields or normalizes groups of fields, or an implementation written by hand because behaviour different from the derived one is wanted. A type declared separately for a boundary whose needs are expected to diverge from the other's, such as a storage record beside an API message with a translation layer between them, is its own structure and not a form of the other, even while their members are largely the same; the rule reaches a form that has to change whenever its declaration changes. An interface that a consumer declares with only the methods it uses, where the language's idiom places an interface with the code that uses it, is outside the rule while few modules declare it; once many modules of a large codebase declare the same interface identically, each copy is in reach, and the interface is declared once and imported by its consumers. Generated output committed to the repository beside its source, as a package that its clients fetch as source requires, is not a hand-written copy when it carries the marker. A tolerance in the project context that names a hand-kept form and the reason no derivation or generator is used for it rejects the finding.

## Validator
Grep the added lines for hand-written constructor, equality, hash and string methods, implementations of derivable standard behaviours, a string-name method on a constant type, interface, struct, enumeration, record, data-class, schema-model and object-type declarations, literal-union type declarations, and field tags, annotations or serialization derives that name wire or column fields. For a method, open its type and check whether the method only restates the type's fields or constants as the language's derivation feature or an available generator would produce them, and whether that feature applies to the type. For a type, interface or literal-union declaration, search the repository at scope callers for a declaration it repeats: a type with the same members, or the same members made optional, read-only or renamed; a declared value list holding the same literals; the same interface declared identically in many other modules; or a schema file (an interface definition, an API specification, database queries) that already describes the structure and that a generator could turn into this code; then check that the added declaration has to change whenever that declaration changes, rather than serving a boundary whose needs diverge from it, such as storage beside an API. For tags or annotations, check whether the field list restates such a schema file by hand. For a file the diff adds that a generator wrote, check that its top carries a generated-code marker; for a hunk that changes a file carrying such a marker, check that the diff also changes the file's source or regenerates the file whole. Skip a member whose behaviour differs from the derived one (validation, defensive copies, normalization, a display format for end users), a form no available derivation or generator can produce, an interface a consumer declares with only the methods it uses while few other modules declare it identically, a type kept separate for a boundary whose needs diverge (a storage record beside an API message, with a translation between them), marked generated output that the diff regenerates from its source, and a form a project tolerance names. Validator question: **Does the diff write out by hand a form of a schema, type, enumeration or interface that one declaration in the repository could produce through a derivation feature, a generator or an import, or add generated output without a generated-code marker, or edit marked generated output by hand?** Yes → flag.

## Finding output
When the validator answers yes, the finder emits one finding (`rule_id: DSN-24`, severity minor, `file`, `symbol`, `code` = the added line that opens the hand-written form (the method signature, the type or interface declaration, the tag or annotation line), or the first changed line of the generated file, `fix` = the form replaced, in the file's language, by the derivation feature, by a type computed from the existing type or value, by an import of the one shared declaration, or by a generator run on the schema file with the generated-code marker on its output, `rationale` = names the one declaration or schema file the form restates, the forms that restate it, and the change that would have to be repeated in each).
