# Kind agreement — brief

## Kinds of statement

| Kind | What it is | What it rests on | Example |
|--|--|--|--|
| decision | a choice: a goal, a priority, a taste, a threshold | the owner's word | "figures on a page are calm" |
| definition | the name of a thing | agreement | "a card is one checkable rule" |
| norm | what an accepted document prescribes: a standard, a specification, a regulation | the document, opened, with its issuer and version | "exit status zero means success" |
| claim | a statement about how the world works | a test | "with this paragraph the agent reads the file before editing more often" |

A norm shows that a practice is accepted; whether the practice works better is a separate claim. A statute and an industry regulation are norms. A logical inference is worth what its premises are worth and forms no kind of its own.

## Reading rule

The kind of a rule is the kind of what the rule rests on, as its provenance line shows it.

- `claim`: the line names a test of the claim that the rule's technique works — a study with a measurement, a benchmark, a run of our own. A line that names both such a test and a document is a `claim`.
- `norm`: the line's ground is a document that prescribes or describes the practice — a standard, a specification, official documentation, a style guide, a rule of a static analyser.
- `decision`: the line's ground is the project's own choice — a house convention, the owner's word, the repository's rule.
- `definition`: the rule fixes what a term means and asserts nothing about what works.

### ERR-12

Title: An expected, recoverable failure is returned or raised to the caller, and code outside the entry point and start-up does not panic, exit or abort the process on it

When a routine meets a failure that is expected in normal operation — malformed data handed to a parser, a remote reply saying a rate limit was hit, values from a caller that make no sense where continuing is neither insecure nor harmful — it returns an error or raises one to its caller, so that the caller decides how to handle it. Stopping the process on a failure belongs to the entry point, which turns an unhandled error into an exit status, to the start-up code of a program that owns its process, when it cannot set the program up, and to a state that has become irrecoverable.

### CODE-58

### JAVA-148

Title: A retry waits with exponential backoff and random jitter, never a fixed or lockstep delay

The delay between retry attempts grows with the attempt number and includes a random component — `random(0, min(cap, base * 2^attempt))` or the library's exponential-random interval — so that clients that failed at the same moment do not all retry at the same moment; an immediate retry or a delay computed identically by every client is not a backoff.
