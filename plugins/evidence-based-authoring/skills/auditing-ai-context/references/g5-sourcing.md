# G5 — Sourcing & Evidence

Sub-agent task: audit every rule, threshold, and prescription for traceability to a named source. Emit JSON patches per `../SKILL.md#patch-format`. Unsourced rules are the most likely dead weight — Yang 2505.13360 §3.1 found ~23.3% of authored rules came from "LLM brainstorming" with no production grounding.

## Why this group matters

The repo's own CLAUDE.md mandates the Evidence-Based Rule: every checklist item must trace to academic research, technical standards, or verified hands-on experience. The cost of an unsourced rule is asymmetric — it consumes the same budget as a sourced rule but tends to fail under the bundling tax first (Yang §3.4) because the model cannot anchor its application to a remembered failure mode.

Failed-trajectory error analysis produces the most reliable rules (~41.7% of production rules); existing-prompt mining is second (~35%); LLM brainstorming third (~23.3%) — and brainstorm-only rules disproportionately under-perform.

---

## R-50 — Every rule MUST cite a traceable source

**Statement.** Every prescription — rule, threshold, anti-pattern, recommended pattern — must trace to one of:

| Source class | Example |
|--|--|
| Peer-reviewed paper | arxiv ID + section anchor |
| Technical standard | RFC number + § |
| Vendor / framework doc | Stable URL or doc-version |
| Dated hands-on note | "Verified <date> on <project>" |

Rules without an attributable source must be cut or marked provisional.

**Why.** The repo CLAUDE.md is explicit ("No traceable source → do not add"). Empirically, the brainstorm-derived 23.3% cohort fails most often when bundled. Even good ideas without a source can't be defended against future "delete this rule, it costs tokens" pressure.

**How to apply.** For each rule sentence, look in the surrounding 5 lines for a source pattern: `(Author <Year>)`, `(<Author> §<N>)`, `RFC <N>`, `<arxiv-id> §<N>`, `Verified <date>`, link to a stable doc. If absent → flag.

**Bad → Good.**

```
bad:  "Always use 3-5 examples — too few under-trains, too many confuse."
      (no source)

good: "Use 2–5 diverse examples; 3 excellent beats 10 mediocre. Place most-relevant
      example last — models weigh final examples 2–3× more. Inconsistent label/format
      across examples cuts effectiveness up to 40% (Khan 2510.22251 §6.2.1)."
```

**Patch shape.**

```json
{
  "rule_id": "R-50",
  "location": {"section": "<heading>", "line_hint": <int>},
  "current": "<unsourced rule>",
  "proposed": "<rule with citation appended OR 'mark as provisional / cut'>",
  "justification": "No traceable source; brainstorm-only rules fail under bundling tax (Yang §3.1, §3.4).",
  "severity": "medium",
  "needs_human": true
}
```

`needs_human: true` because the sub-agent cannot invent a citation. The patch is a request: either supply one, or accept removal.

## R-51 — Citations MUST use stable structural anchors (chapter + §, arxiv-id + §, RFC + §)

**Statement.** See R-41 in G4 — same rule. G5 audits sourcing specifically; G4 audits any reference. When G4 has flagged R-41 already, G5 omits.

If a citation in this file uses *only* a stable anchor (good), G5 does not emit a patch. If it has both anchor and page/line (also good), G5 does not emit. If it has only page/line, see R-41 (G4 owns the patch).

## R-52 — LLM-self-authored context costs +20–23% tokens for −0.5% to −2% success — must be audited

**Statement.** Auto-generated AGENTS.md / CLAUDE.md from an LLM in the same session that will consume it regresses: Gloaguen 2602.11988 §4.2 (cost +20–23% tokens, −0.5% to −2% success) and Li 2602.12670 Finding 3 (self-generated SKILL.md averages −1.3pp; Codex+GPT-5.2 −5.6pp; only Opus 4.6 marginal +1.4pp).

Where a file declares "auto-generated", "produced by LLM", or "generated from <code>/<config>", flag — propose either deletion or human-author audit pass. Where the file's *style* looks LLM-generated (uniform paragraph length, vague abstractions, hedging openers, lack of concrete failure modes) but has no provenance marker — flag as suspect.

**How to apply.** Heuristics for LLM-generated content:

| Signal | Strength |
|--|--|
| Explicit "generated by" / "auto-generated" marker | strong |
| Every section has the same paragraph length (4–6 lines, no fragments) | medium |
| Hedging openers: "It is important to", "Make sure to", "Be aware that" | medium |
| Abstractions without examples or numbers | medium |
| No source citations anywhere | medium (combined with above) |
| Section names are generic ("Overview", "Best Practices", "Guidelines") with no domain specificity | weak |

Three or more medium signals → flag.

**Patch shape.**

```json
{
  "rule_id": "R-52",
  "location": {"section": "<whole file or specific section>"},
  "current": "<excerpt or summary of LLM-style content>",
  "proposed": "Delete or rewrite by human; validate with a fresh agent on real tasks.",
  "justification": "Style signals suggest LLM self-authoring; LLM-generated context regresses (Gloaguen §4.2, Li Finding 3).",
  "severity": "medium",
  "needs_human": true
}
```

## R-53 — Failed-trajectory error analysis is the strongest rule-source — prefer it on rewrites

**Statement.** When proposing new rules or rewriting existing ones, the source hierarchy is:

| Rank | Source | Share of production rules (Yang §3.1) | Quality |
|--|--|--|--|
| 1 | Failed-trajectory error analysis | ~41.7% | highest |
| 2 | Existing-prompt mining | ~35.0% | medium-high |
| 3 | LLM brainstorming | ~23.3% | lowest, highest failure |

G5 does not emit patches for this rule directly; it informs the *justification* field of other patches. When proposing a new rule, the patch should note which source class was used. When auditing an existing unsourced rule (R-50), G5 should ask whether the rule traces to a recorded failure trajectory (best), an existing-prompt convention (medium), or pure brainstorm (cut).

## R-54 — Quantified claims MUST carry their numbers

**Statement.** When a source supports a claim with a measured effect, the rule must preserve the number. "Improves accuracy" is not equivalent to "improves accuracy by 18.6pp." The number is the load-bearing part of the citation.

**Why.** Stripped numbers turn a falsifiable claim into a vague gesture. Yang §3.3 found "unspecified requirements are ~2× as likely to regress across model / prompt changes" — vague claims are the unspecified-requirements analog at the rule level.

**How to apply.** For each cited claim, check whether the number is present in the file. If the source has a number and the rule omits it → flag.

**Bad → Good.**

```
bad:  "Reliable@10 testing catches failures."
good: "Reliable@10 testing exposes failure modes hidden by single-prompt accuracy —
      up to 61.8pp reliability drops measured between nominal accuracy and reliable@10
      (Dong 2512.14754 §2.2)."
```

**Patch shape.**

```json
{
  "rule_id": "R-54",
  "location": {"section": "<heading>", "line_hint": <int>},
  "current": "<de-quantified claim>",
  "proposed": "<claim with the source's number restored>",
  "justification": "Quantified claim flattened to vague gesture; restoring number restores falsifiability.",
  "severity": "low"
}
```

## R-55 — Cited papers MUST be referenced once with full ID; subsequent mentions short-form

**Statement.** First mention: `Author <Year> <arxiv-id> §<N>`. Subsequent mentions in the same file: `<Author> §<N>` or `<arxiv-id> §<N>`. Repeating the full citation devalues it and inflates length.

**How to apply.** Count occurrences per citation. If any citation appears with full ID + year > twice → propose shortening the second+ occurrences.

**Patch shape.**

```json
{
  "rule_id": "R-55",
  "location": {"section": "<heading>", "line_hint": <int>},
  "current": "<repeated full citation>",
  "proposed": "<short form>",
  "justification": "First mention full, subsequent short.",
  "severity": "low"
}
```

## Output protocol for this sub-agent

1. Build a citation inventory: for each cited source, list every line that references it.
2. For each rule sentence: present-source-or-flag (R-50).
3. Run the LLM-style heuristic (R-52) once across the file; emit at most one patch per section.
4. Defer to G4 R-41 on locator stability; do not duplicate.
