# Research note — Python classes, dataclasses and enums

Topic `python-classes-dataclasses-enums` of group python, domain `design`, id prefix `PY`. Formulation locators: Ruff RUF, PLW, B, FURB; Pylint; CPython dataclasses, enum, abc.

The catalogs check how Python classes are declared rather than what they compute: Ruff (RUF008, RUF009, RUF012, RUF045, RUF049, RUF066, RUF074, PIE794, PIE796, B019, B024, B027, B903, UP008, UP042, FURB189, the PLW/PLE/PLR ports of Pylint), Pylint (W1641, W0231, W0237, W1518, E1519, E1520, W0201, W0223, W0233, W0236, W0213, R6101, R6105, R6301) and SonarSource python (S2638, S2325, S8490, S8500, S8504, S8505, S8512, S8514, S8685, S9156) look at class-body defaults and dataclass fields, the __eq__/__hash__ pairing, rich comparisons, ABC declarations, Enum values, override signatures, base-initializer calls, method caches and dispatch decorators. The CPython documentation states the semantics behind most of them: a class body runs once and its assignments are class attributes (tutorial, dataclasses 'Mutable default values'), dataclass fields are only annotated names, __eq__ without __hash__ sets __hash__ to None, a derived __init__ must call the base one, comparison operators imply no relationships (PEP 8 recommends all six or total_ordering), ABCMeta enforces only @abstractmethod members, equal Enum values make aliases, functools caches keep self alive, singledispatch dispatches on the first argument. Positions differ in four places, each separated by a sourced condition: Ruff and Pylint ask for __hash__ beside every __eq__ while the data model says a mutable class should stay unhashable; Ruff B019 and Sonar S9156 report every cached method while Pylint W1518 and the CPython FAQ treat a bounded lru_cache as a technique; Sonar S2638 exempts renamed parameters for pre-3.8 code while Pylint W0237 reports them; Ruff PIE796 calls a repeated Enum value a likely mistake while the enum HOWTO documents aliases. Ten rules are carded; one candidate is an instance of DSN-36, one is out of scope because CPython raises at class creation, and the rest are folded into a card or held behind the cap.
