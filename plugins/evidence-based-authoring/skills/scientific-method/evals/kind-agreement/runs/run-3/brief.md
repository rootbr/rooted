# Kind agreement — brief

## Kinds of statement

| Kind | What it is | What it rests on | Example |
|--|--|--|--|
| decision | a choice: a goal, a priority, a taste, a threshold | the owner's word | "figures on a page are calm" |
| definition | the name of a thing | agreement | "a card is one checkable rule" |
| norm | what an accepted document prescribes: a standard, a specification, a regulation | the document, opened, with its issuer and version | "exit status zero means success" |
| claim | a statement about how the world works | a test | "with this paragraph the agent reads the file before editing more often" |

A norm shows that a practice is accepted; whether the practice works better is a separate claim. A statute and an industry regulation are norms. A logical inference is worth what its premises are worth and forms no kind of its own.

## Reading rule

The kind of a rule is the kind of what the rule rests on, as its provenance line shows it.

- `claim`: the line names a test of the claim that the rule's technique works — a study with a measurement, a benchmark, a run of our own. A line that names both such a test and a document is a `claim`.
- `norm`: the line's ground is a document that prescribes or describes the practice — a standard, a specification, official documentation, a style guide, a rule of a static analyser.
- `decision`: the line's ground is the project's own choice — a house convention, the owner's word, the repository's rule.
- `definition`: the rule fixes what a term means and asserts nothing about what works.

### DSN-21

Title: A block of four or more lines or a routine body that repeats another to do the same thing is written once as a routine each place calls

When added code repeats a block found elsewhere in the change or in the repository, and the copies are meant to do the same thing, so that a fix or a change of behaviour in one would have to be made in the other, the block is written once as a routine that each place calls. A block counts from four lines, not counting blank lines, comments, documentation strings, imports and signatures. Copies that differ only in the values, names or types they operate on are one block: the routine takes the values as parameters, and the types as type parameters where the language has them. An added routine whose body of two or more lines is identical to another routine's body is the same defect at routine level: one routine calls the other, or both call one shared routine.

### CODE-22

Title: A variable or constant is declared in the narrowest scope that holds all its uses, unless narrowing it would deepen nesting or its value is needed after that scope

Each variable and each constant is declared in the smallest scope that contains all its uses. A variable that only one block, loop or conditional uses is declared inside it, in that statement's own initializer where the language offers one. A variable whose value one loop iteration or one call of its routine leaves for the next stays declared outside that loop body or routine. A private field that every routine using it assigns before it first reads it becomes a local variable of those routines. In a language with a constant declaration usable inside a routine, a constant whose value is a literal, or an expression over literals and other constants, is declared inside the routine that uses it unless several routines or files use it or it is part of the module's external contract. Where the language offers both a block-scoped and a function-scoped declaration form, the block-scoped form is used. The declaration stays in the wider scope when narrowing it would conflict with reducing nesting, or when its value is needed outside the narrower scope.

### META-09

Title: An invariant keeps its number across revisions and a retired number is never given to another rule

### ERR-09

Title: A thrown or returned error has a type that says what failed, never a string or other non-error value and never a generic exception class

An error that code throws, raises or rejects a promise with is an object of an error type, and that type names the failure: a specific type the standard library provides when one matches, or a type of the code's own. A routine's declared list of thrown types names those specific types too. A public routine that reports failure through a result value gives it an error type that implements the language's error interface and names the failure. Failures that callers handle differently get distinct types or variants, and the hierarchy follows the distinctions the catching code needs rather than the places the errors are raised. In a language that lets any value be thrown and whose base error object records a stack trace when it is created, that base object stays acceptable where no caller needs to tell this failure apart from others.

### CODE-77

Title: A loop variable the loop header advances is changed only by that header, never inside the body to skip elements or to end the loop

In a loop whose header initializes, tests and advances a counter, only the header changes the counter: the body does not assign to it, increment or decrement it, or hand it to code that updates it. The body skips an element with a test, or with a separate flag that the next pass checks before it continues; it ends the loop early with break, or with a return from a routine that holds the loop; and the header's termination test compares the counter against a bound that does not change while the loop runs. A counter that must be updated in the body belongs in a while loop instead. In a loop that visits each element of a collection or a range, the body does not reassign the loop variable either, and where loops open no scope of their own, an inner loop does not reuse an enclosing loop's variable name.
