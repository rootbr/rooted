# Code that selects a handler by a key from an untrusted source looks it up in a closed table of handlers, or confines a reflective method lookup to a fixed name prefix, so the key cannot reach an arbitrary method or function

## Thesis
When the key that selects which routine to call comes from an untrusted source — a request parameter, a received message, any value an outside party controls — the code looks the key up in a closed table: a map from each permitted key to its handler, whose lookup answers only with the entries the code put in it and never with members the map inherits from its type, or a fixed list of permitted names that the key is checked against before any lookup. A reflective lookup of a method on one object, by a name built from such a key, is confined instead by a fixed prefix that only the dispatchable methods carry, so that the lookup reaches only those methods. A lookup by such a key among all the members of an object, the functions of a module or global namespace, or the members a table inherits, with neither a list of permitted names nor, for a method of one object, such a prefix, is the defect.

## Rationale
Without a fixed prefix, a reflective lookup by a name that comes from an untrusted source lets an attacker call any method on the object. When values an attacker supplies decide which class to instantiate or which method to invoke, the attacker can create control flow paths the developers never intended, which may bypass authentication or access control checks or make the application behave in an unexpected manner. Calling a user-controlled method on the global object can invoke the code-evaluating function that object holds, and indexing the global namespace with data that is not a literal can let an attacker execute arbitrary code. A user-controlled name can also break the call itself: the member it reaches may not be a function, or it may be a standard method that most objects inherit, called with the wrong number or kind of arguments; each throws at run time, and an unhandled throw of that kind can be used to mount a denial-of-service attack. The remedies follow the same line: a map in place of a general object takes the lookup by a user-controlled name off the object's members; a list of permitted names, or at the least a check that the entry is the table's own and not inherited, keeps the inherited methods out of reach; a fixed prefix confines a reflective lookup to the methods that carry it.

## Example
```python
bad:  def handle(self, request):
          return getattr(self, request.args["action"])()
good: def handle(self, request):
          actions = {"start": self.start, "stop": self.stop}
          action = actions.get(request.args["action"])
          if action is None:
              raise ValueError("unknown action")
          return action()
```

## Limits
The defect needs a name an untrusted party controls: a lookup by a literal, a constant or an enumeration member is not a finding, and a project context that records the key's source as trusted rejects the finding. The fixed prefix is the remedy given for a method looked up on one object; for the functions of a module, the global namespace or the global object, the remedies given are a list of permitted names, a separate map, or code that stops indexing the namespace, and the prefix allowance, which rests on a statement about the methods of one object, does not extend there. What the code does with a key the table has no entry for, the choice of a class to instantiate by a name built from such a key, and the validation of the input value where it enters the program, are outside this rule, which judges only which routines a key can reach.

## Validator
Grep the added lines for a call of a routine looked up by a runtime name: a reflective attribute or method lookup whose name argument is not a literal, a subscript of an object, a module namespace or the global object by a computed key followed by a call, a subscript keyed by a request, message or event value, and an index of the global or local namespace. Within the hunk, trace the key back through assignments and string building in the enclosing routine to where it enters. Treat the key as untrusted only when the hunk shows it read from a request parameter, path segment, header or body field, a received message or event, or another value an outside party supplies; a key that arrives as a parameter with no source in the hunk is not shown untrusted. Pass the lookup when the hunk checks the key against a fixed list of permitted names before the lookup; when the table is a map that holds only the handlers and whose lookup cannot answer with an inherited member; when the table holds only the handlers and the hunk checks that the entry is the table's own and not inherited; and when a reflective lookup of a method on one object builds the name as a fixed prefix plus the key and no other member of the object, inherited and special members included, carries that prefix. An own-entry or membership check on the global object, a module or global namespace, or an object that holds more than the handlers does not pass: it still admits every function that object or namespace holds, the code-evaluating function of the global object among them. Validator question: **Does added code call a method or function chosen by a key the hunk shows coming from an untrusted source, through a lookup among all the members of an object, the functions of a module or global namespace, or a table that also answers with inherited members, with no check against a fixed list of permitted names, no check that the entry is the own entry of a table that holds only the handlers and, for a method of one object, no fixed name prefix that only the dispatchable methods carry?** Yes → flag.

## Finding output
When the validator answers yes, the finder emits one finding (`rule_id: CODE-14`, severity major, `file`, `symbol`, `code` = the lookup-and-call line and the line that reads the key from the untrusted source, verbatim from the diff, `fix` = a map from each permitted key to its handler, a check of the key against a fixed list of permitted names before the lookup, or, for a method of one object, a fixed prefix on the looked-up name, in the file's language, `rationale` = what the untrusted key can reach beyond the intended handlers, such as any method of the object, an inherited standard method or a code-evaluating global function, and the run-time failure such a member causes when called).
