# Research note — Python logging and diagnostics

Topic `python-logging-and-diagnostics` of group python, domain `errors`, id prefix `PY`. Formulation locators: Ruff G, LOG; Pylint W1203; CPython logging HOWTO.

Python's catalogs check how code calls the stdlib logging and warnings modules: Ruff G001-G004, Pylint W1201-W1203, SonarSource S8554 and Ruff RUF065 flag a log message formatted before the call; Ruff TRY400 and Sonar S8572 flag logger.error in an except handler where logger.exception attaches the traceback; Ruff LOG004 and LOG014 flag exception information requested outside a handler and LOG007 an exception() call with exc_info=False; LOG001 and LOG002 flag a logger not obtained through getLogger(__name__); LOG015 flags calls on the root logger; G101 and S8554 flag extra keys that clash with LogRecord attributes; Ruff and flake8-bugbear B028 flag warnings.warn without stacklevel. The CPython logging HOWTO and reference state the semantics behind them: formatting of message arguments is deferred until it cannot be avoided, a true exc_info adds exception information and otherwise falls back to sys.exc_info(), Logger.exception should only be called from an exception handler, Loggers should never be instantiated directly, the module-level functions call basicConfig() when the root logger has no handlers, and extra keys should not clash with the logging system's keys; the warnings reference says stacklevel makes a warning refer to the caller. Positions differ on lazy %-arguments against f-strings: Ruff, Sonar and the Google Python style guide reject a pre-formatted message, while Pylint documents f-strings as another reasonable option chosen in configuration; the sourced separating condition is that passing arguments lets the logger skip formatting when the level filters the record out, which matters for arguments with an expensive __str__ or __repr__ (Pylint W1203), and that some logging implementations collect the unexpanded template as a queryable field (Google 3.10.1), so the card yields where a project's linter configuration has disabled the f-string check. Sonar S8572 also prefers exception() over error(exc_info=True), which Ruff TRY400 does not flag; the card accepts either. Of the owned subjects, logging configuration at the entry point appears only through the root-logger card's implicit basicConfig(); __debug__ and timeit had no candidate in this run.
