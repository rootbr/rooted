# Code that measures, indexes, slices or truncates a string counts in the unit the operation means, the unit a storage or protocol limit is declared in and grapheme clusters for user-perceived characters, and never takes one unit's count or offset for another's

## Thesis
Code that measures, indexes, slices or truncates a string is explicit about which view of the string it counts, bytes, code units, scalar values or grapheme clusters, and counts in the view the operation means. A limit on the size of the encoded text, such as a buffer, a protocol field or a column sized in bytes, counts the units of the encoding the text is stored or sent in, measured on the encoded form, and an offset handed back to slice the same string stays in the unit it was obtained in. A limit declared in characters, such as a column that stores up to n characters rather than bytes, counts in the unit the store defines. A limit or position the user perceives as characters, such as the cut point of a truncated label, counts grapheme clusters through a grapheme-boundary API. A count or offset taken in one unit is used only in that unit. A split whose parts are meant as characters splits at grapheme-cluster boundaries, and a character made of several code points is not written directly inside a regular-expression character class, which dissolves it into its code points.

## Rationale
A string's built-in length counts one fixed unit that differs between languages, such as the bytes of its encoding, its UTF-16 code units or its code points, and none of these three units is a grapheme cluster. A 12-letter Cyrillic word takes 24 bytes to encode in UTF-8, so its byte length is its encoded size and may not be what a human considers its length. A code unit is not a character either: one character may take one or two UTF-16 code units, a letter with a combining mark may be two code points and one user-perceived character, and an emoji sequence joined by zero-width joiners is several code points treated as one visual unit. An offset counted in another unit can land inside a character. Slicing a string that must hold valid UTF-8 through part of a character's bytes panics at runtime, and slicing a string that may hold arbitrary bytes there leaves bytes that are not valid UTF-8; splitting on the empty string cuts by code units or code points and separates a character made of several, down to the halves of a surrogate pair where strings are UTF-16; and a regular-expression character class dissolves a multi-code-point character into its code points and matches each one alone. An index obtained from a known valid position in the same string, in the same unit, slices safely.

## Example
```typescript
bad:  function truncateLabel(title: string, max: number): string {
        const chars = title.split("");
        return chars.length > max ? chars.slice(0, max).join("") + "…" : title;
      }
good: function truncateLabel(title: string, max: number): string {
        const seg = new Intl.Segmenter(undefined, { granularity: "grapheme" });
        const chars = Array.from(seg.segment(title), (s) => s.segment);
        return chars.length > max ? chars.slice(0, max).join("") + "…" : title;
      }
```

## Limits
An offset that comes from a known valid position in the same string, such as an index returned while iterating that string's characters, slices correctly; the rule asks only that count and use share a unit. Where every code point of the text is encoded as one unit, the code-unit and code-point counts coincide: for Latin, Cyrillic and well-known CJK text a UTF-16 code-unit count should match the number of Unicode characters, while for emoji, mathematical symbols and obscure Chinese characters the difference may need to be accounted for. A letter with a combining mark is still two code points and one user-perceived character in such text, so a limit the user perceives as characters counts grapheme clusters there too. Whether every operation that means "character" should count grapheme clusters is contested. One position holds that grapheme clusters are the meaningful view, since grapheme-cluster boundaries try to match what a user would think of as a character. The other treats the built-in units as legitimate counts, since a code-unit count should match the characters of common scripts and a standard library can leave grapheme segmentation to external libraries. The separating condition is what the count is for: an encoded-size limit counts the units of the encoding the text is stored or sent in, measured on the encoded form, which the built-in length returns only where the string is held in that same encoding; an offset handed back to slice the same string stays in the units the slice operation accepts; a limit or position the user perceives as characters uses grapheme clusters. Which encoding of the same visible text to store, and how to compare two encodings of it, lie outside this rule.

## Validator
Grep the hunk for a string length compared with a number or limit, a substring, slice, character-at or range-index operation on a string, a split on the empty string, a regular-expression character class holding non-ASCII characters, and names such as truncate, ellipsize or max length. For each hit, read the hunk to learn what the count or offset is for: the size of a buffer, file, protocol field or column, and whether that limit is declared in bytes or in characters, an offset to cut the same string again, or a number of characters the user sees. Trace each offset to the operation that produced it and note the unit that operation counts in. Validator question: **Does the hunk count, index, slice or truncate a string in a unit other than the one its purpose needs, the stored or sent encoding's units, counted on the encoded form, for an encoded-size limit, the store's own unit for a limit declared in characters, the slice operation's units for a same-string offset and grapheme clusters for a user-perceived character limit, or split a string whose parts are meant as characters into code units or code points, or write a character made of several code points directly inside a regular-expression character class?** Yes → flag.

## Finding output
