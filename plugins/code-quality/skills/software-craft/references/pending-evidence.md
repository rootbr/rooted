# Pending evidence — rules held back

A rule listed here has no card and no id. It ships when an admissible source — academic research with an arXiv id or DOI, a technical standard or official documentation by section, or verified hands-on experience in an openable form — is found to state the claim as the rule words it, or, for a contested rule, when a sourced condition separates the cases. Each entry keeps the rule's original wording, its topic, its formulation source, what was searched and what would unblock it, so the next search starts where the last one stopped.

Entry shape: `domain · topic slug · original wording · formulation · searched · what would unblock`; a contested rule without a separating condition begins with `no separating condition ·` and lists both positions.

## errors
- no separating condition · errors · error-and-exception-handling · "ASVS requires a last-resort handler that catches all unhandled exceptions, so that error details reach the logs and one error does not take down the whole process. - tests · test-doubles · "A fake keeps fidelity to the real implementation's API contract. Where it cannot reproduce a behaviour, it fails fast, for example by raising an error when an unsupported code path runs, instead of silently returning a default the real implementation would never return." · formulation: SEG ch. 13 'The Fidelity of Fakes' · searched: The three layers searched for a statement that a fake must fail on unsupported paths. Any of these would unblock the rule: an official documentation page or tool rule that requires a fake or hand-written double to raise on unimplemented members (for example the documented contract of a standard-library in-memory implementation), or a study that ties silent default returns in fakes to missed defects. · what would unblock: The only statement is SEG ch. 13, a trade book, which counts as formulation and not evidence.

- no separating condition · code · naming-identifiers · "Code Complete reports that debugging effort was lowest when variable names averaged 10 to 16 characters (one 1990 COBOL study; 8 to 20 almost as good), and several linters ship fixed per-name bounds: ESLint id-length minimum 2, PMD ShortVariable minimum 3 and LongVariable 17, clang-tidy readability-identifier-length minimum 3.
