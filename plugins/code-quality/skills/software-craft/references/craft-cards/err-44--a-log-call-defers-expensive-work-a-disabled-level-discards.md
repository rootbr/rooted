# A log call at a level that may be disabled defers expensive work on its arguments or message until the logger decides to emit the record

## Thesis
A log call at a level that the logger's configuration may discard, such as debug, trace or a verbosity level, defers expensive work on its arguments or message until the logger has decided to emit the record. The work is expensive when an argument comes from a call such as one that collects system status, explains a query or computes an expensive value, when converting an argument to text is expensive, or when profiling shows that logging takes significant time. The call defers the work by a means its logging facility provides: it passes the value itself, so that the logger converts and formats it only for an enabled record; it passes a function or a value type that the logger invokes only for an enabled record; or it checks that the level is enabled before it computes the argument. A log statement that is a macro which evaluates its arguments only after the facility's filters have accepted the record defers the work already.

## Rationale
Where a log statement is an ordinary function or method call, its arguments are evaluated even when the logger then discards the event because its level is disabled: a status that a call collects for a disabled level is collected anyway, and the logger throws the event away. Where it is a macro that tests the level before it evaluates its arguments, the work runs for a discarded record only when a filter that the macro does not test discards it, such as a per-target filter behind a test of a global maximum level, and a level check that consults that filter defers it. One common configuration logs at info or higher and suppresses debug logging until it is needed, a facility may by default track only warning and higher, and a log call at a level the configuration disables, such as a debug log in production, can effectively do nothing while its arguments may still be evaluated before the call. Passing the values to the logger defers the formatting, which the logger skips when the record is filtered out by level; it does not defer computing an argument, so an expensive call in the argument list still runs. A function that the logger invokes, or a value type whose conversion the logger calls, only for an enabled record moves the computation itself behind the logger's level decision, and passing the value rather than its text also keeps the value's structure for a handler that emits it as structured data. A level check runs the guarded code only when the event would be created at that level, so the expensive calls inside it are never made while the threshold is set above that level. Where the check itself costs more than wanted, as for a deeply nested logger whose explicit level is set only high in the hierarchy, or where a method call in a tight loop is to be avoided, its result can be cached in a local or instance variable and recomputed only when the logging configuration changes while the program runs. Where a facility offers a convenient form that evaluates its arguments and a slightly more verbose form that checks the level first, the convenient form carries the risk of calling an expensive function while the level is turned off. Which means a call uses depends on what its logging facility offers.

## Example
```python
bad:  log.debug("cache state: %s", json.dumps(cache.snapshot(), indent=2))
good: if log.isEnabledFor(logging.DEBUG):
          log.debug("cache state: %s", json.dumps(cache.snapshot(), indent=2))
```

## Limits
The rule is contested where the work is cheap. One position asks for a level check, or for parameters, formatters or a deferred function, wherever a log call creates or manipulates a string or makes any method call, and its check covers every level from trace to error by default. The other position calls a formatted string in a log call another reasonable option, and one linter places its rules against eagerly formatted logging messages in a category that is off by default and that it describes as noisy or overly opinionated, suggesting changes that many of the language's users disagree with. The condition that separates the cases is the cost of the work a disabled level would discard: passing the arguments to the logger matters when converting them to text is expensive, and the advice to defer computation applies when profiling shows that logging takes significant time. A log call that formats literals, variables, field reads or getters into its message eagerly is outside the rule when converting them to text is cheap, and so is a log call in a failure handler that runs only on an exceptional path, where the performance penalty is unimportant; a handler that the program's normal flow passes through, such as the miss branch of a lookup written as a try and a catch, stays within the rule. Each means of deferral follows the rule, whether passing the value, a deferred function or value type, or a level check; which alternatives exist depends on the logging facility. A project whose linter configuration allows formatted strings in log calls tolerates eager formatting of cheap values, and an expensive argument stays a finding under that tolerance. The rule judges when the work happens; which level a record takes, what its message says and whether its values travel as structured fields are outside it.

## Validator
Grep the added lines for a log call at a level the configuration may discard — debug, trace, fine, finer, finest or a verbosity level, and info or warning where the project sets a higher minimum — whose arguments or message hold a call, a serialization, a concatenation or a formatted string. For each hit, read the hunk around it. Skip the call when it sits inside a check that the same level is enabled or after an early exit taken when that level is disabled, including a cached enabled flag; when the log statement is a macro that evaluates its arguments only after the facility's filters have accepted the record; when the work reaches the logger as a function or a value type that the logger invokes only for an enabled record; when it sits in a failure handler, such as a catch, except or rescue block or an error branch, that runs only on an exceptional path and not on the program's normal flow; and when its arguments are literals, variables, field reads or getters whose conversion to text is cheap. Name the work that runs before the call: a call that collects, queries, explains, serializes, dumps or walks a structure; a conversion to text that the value's type or the surrounding code shows to be expensive, such as a large collection or a whole document rendered as text; or formatting inside a loop or path that the project's profiling marks as hot. Validator question: **Does an added log call at a level the configuration may discard run expensive work on its arguments or message before the logger decides to emit the record, with no level check guarding that work and no deferred form around it?** Yes → flag.

## Finding output
When the validator answers yes, the finder emits one finding (`rule_id: ERR-44`, severity minor, `file`, `symbol`, `code` = the added log call with the expensive argument or eagerly built message, verbatim from the diff, `fix` = the same record with the work deferred by the facility's means — the value passed for the logger to convert and format, a function or value type the logger invokes only for an enabled record, or a check that the level is enabled around the computation — in the file's language, `rationale` = the work the call runs, the level at which the record is discarded, and that the work runs even when the record is discarded).
