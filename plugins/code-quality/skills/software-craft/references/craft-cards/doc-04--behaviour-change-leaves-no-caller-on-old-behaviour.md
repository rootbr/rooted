# A change to what an existing routine returns, raises, mutates or requires for inputs its callers already pass leaves no caller in the repository that still depends on the old behaviour

## Thesis
A change that alters what an existing routine does for inputs its callers already pass — its return values, the errors it raises or returns, the state or arguments it mutates, the preconditions it requires, or the defaults it applies — leaves every caller in the repository either unaffected or updated in the same change. The callers are found through the language server's references query and its incoming-calls query, and through a text search over the whole repository for the routine's name wherever a call reaches the routine without the language server resolving it: a call that names the routine by a string (reflection, a string-keyed registry, configuration, a code generator's template), or a method call on a receiver whose type the language server cannot infer or infers as an interface, protocol or base class whose method the routine implements or overrides.

## Rationale
Finding the code that reaches a changed routine is a reachability question: a search across feasible paths through a program for target statements matching search criteria. In a lab study of 13 developers, half of the bugs the developers inserted were associated with reachability questions; 460 professional developers reported asking questions that reachability questions may answer more than 9 times a day, and 82% rated one or more as at least somewhat hard to answer; in a field study of 17 developers, 9 of the 10 longest activities were associated with reachability questions. In an observational study of maintenance tasks, developers who found relevant code followed its incoming and outgoing dependencies, an average of 65 per developer over a 70-minute session, yet only two of them used the environment's dependency navigation tools more than once; they used less sophisticated tools such as the find and replace dialog instead, and in six cases of using that dialog they did not notice that its "wrap search" option was unchecked and were led to believe that the file had no occurrences of the string. A language server's references request resolves project-wide references for a symbol, and its incoming-calls request resolves the call sites of a routine; one server documents that its references result holds the locations of all identifiers that refer to the symbol, and that dynamic calls are left out of its incoming-calls result because detecting them is not analytically practical, so that result may not be exhaustive, and directs a references query where necessary. A type checker for a dynamically typed language documents that unannotated parameters are common and that a symbol whose type cannot be inferred gets the type Unknown, a special form of Any, and in a hands-on check that type checker's language server left a method call on such a receiver, and a call on a receiver typed as a base class or protocol whose method the routine overrides or matches, out of both the references and the incoming-calls results of the routine. Impact analysis identifies all systems and software products affected by a change request; the rule applies that property at the level of the routine's callers.

## Example
```go
bad:  func Find(id string) (*Item, error) {
          if it, ok := items[id]; ok { return it, nil }
          return nil, fmt.Errorf("find %q: %w", id, ErrNotFound) // was: return nil, nil
      }
      item, err := Find(id)
      if err != nil { return nil, err }
      if item == nil { return Default(), nil }
good: item, err := Find(id)
      if errors.Is(err, ErrNotFound) { return Default(), nil }
      if err != nil { return nil, err }
```

## Limits
A change that alters behaviour only for inputs no caller passes, or only how the routine reaches the same result, keeps every caller's assumption true and needs no caller edit. A new routine has no existing callers, and callers the diff itself updates already satisfy the rule. The references request resolves project-wide references, so callers outside the repository, of a published interface, lie beyond what the queries reach and beyond this rule. A dynamic call, through a function value or a callback, can be absent from the incoming-calls result, as one language server documents; that server's references result names each identifier that refers to the routine, including where it is passed as a value, and that site is followed to its calls. A method call on a receiver whose type the language server cannot infer resolves to no declaration, and a call on a receiver typed as an interface, protocol or base class resolves to that type's method; where the references result does not link a routine to the methods it implements or overrides, neither call appears among the routine's references, and the text search finds both.

## Validator
Grep the hunk for a changed return, raise, error construction, field assignment or guard clause inside a routine that existed before the diff. Compare the routine's old and new bodies and list what changed and for which inputs: the return value, the error, the mutated state or argument, the precondition, the default. Where nothing changed for any input, stop. Otherwise open the callers: run the references and incoming-calls queries on the routine, search the whole repository for its name in string literals, reflection lookups, configuration and generator templates, and in method calls on receivers whose type the language server cannot infer or infers as an interface, protocol or base class whose method the routine implements or overrides, and for each caller the diff leaves unchanged read which inputs it passes and how it uses the result, the error, the mutated state or the default. Validator question: **Does a caller in the repository that the diff leaves unchanged still rely on behaviour the diff removed from the routine for an input that caller passes?** Yes → flag.

## Finding output
When the validator answers yes, the finder emits one finding (`rule_id: DOC-04`, severity major, `file`, `symbol`, `code` = the changed return, error or mutation line of the routine quoted verbatim from the diff, `fix` = the stale caller rewritten for the new behaviour, in the file's language, `rationale` = the stale caller's file and line and the old behaviour it still relies on).
