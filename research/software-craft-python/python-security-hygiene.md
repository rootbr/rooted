# Research note — Python security hygiene

Topic `python-security-hygiene` of group python, domain `input`, id prefix `PY`. Formulation locators: Bandit; Ruff S; SonarSource python.

Python security hygiene as Bandit, Ruff's flake8-bandit S rules, Pylint and SonarSource python check it: hard-coded temporary paths and tempfile.mktemp (S108/B108, S306/B306, Sonar S5443/S5445), eval and exec (W0123/W0122, S307/S102, B307/B102), weak hashes (S303/S324, B303/B324, Sonar S4790), tarfile extraction (S202/B202), urllib scheme audits (S310/B310), shell=True (S602/S604/S605, B602/B604/B605) and yaml.load (S506/B506). CPython's documentation supplies the semantics behind each: tempfile.mkstemp creates atomically with owner-only permissions and mktemp is deprecated since 2.3; eval and exec state that overriding __builtins__ is not a security mechanism; ast.literal_eval does not execute code but is not recommended on untrusted data; hashlib's usedforsecurity flag marks a non-security use; tarfile defaults to the data filter only from 3.14 (PEP 706); urllib.request's opener includes FileHandler and FTPHandler. Positions differ in three places: Pylint offers literal_eval for untrusted strings where the ast documentation advises against it, Pylint presents a restricted exec namespace as a mitigation where the builtins documentation denies it is a security mechanism, and Sonar S4790 asks for SHA-256 even for fingerprinting where Ruff, Bandit and hashlib accept MD5 marked usedforsecurity=False. Six cards result; shell=True and yaml.load are instances of INP-04 and INP-06, and the two Sonar temp-file entries fold into the merged temp-file card. The owned constructs pickle, random for secrets, assert as validation, hard-coded passwords and requests without a timeout reached this topic with no candidate, so this run disposes of none of them; arXiv:2107.12699 (relayed) excluded Bandit B101 for false positives, which bears on an assert candidate if a later triage adds one.
