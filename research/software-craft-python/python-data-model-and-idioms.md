# Research note — Python data model and idioms

Topic `python-data-model-and-idioms` of group python, domain `code`, id prefix `PY`. Formulation locators: Ruff B, PLW, RUF, FURB, SIM; Pylint; CPython datamodel.

The catalogs check this topic's data-model traps mechanically: definition-time defaults (Ruff/bugbear B006, B008, Pylint W0102, Sonar S5717), late-binding closures in loops (B023, W0640, S1515), identity against value (F632, R0123, S5795, S5796, E711, FURB168/169, E721, S6660), always-true conditions (F631, F634, W0199, S5905, W0126, B044, S5797), loop else without break (PLW0120, W0120, S2836), the NotImplemented protocol (S5712, F901) and container truthiness (PLC1802, C1802-C1804, PLC1901), plus a long tail of suggestion-level comprehension, min/max, placeholder and modernisation rewrites. The CPython documentation states the semantics behind each carded rule (tutorial on default values and loop else, the FAQ on lambdas in loops, the reference on identity, assert, truth testing and the for statement, the datamodel on NotImplemented), and PEP 8 states the None, isinstance and empty-sequence idioms. Positions differ in two places: PEP 8 says type comparisons always use isinstance while Ruff E721 accepts `type(obj) is T` for an exact match, so the card flags only the == form; and the empty-sequence idiom holds only for values that are strictly sequences, which Pylint and Ruff state as a caveat. The relayed idiom-performance papers (arXiv:2301.12633, arXiv:2203.14484) report that idioms are faster or slower depending on the idiom and scale, so no comprehension card rests on a performance claim. Ten cards ship; 51 candidates wait under held-cap, 22 fold into another rule, 4 are instances of CODE-23, CODE-31 and CODE-38, and 3 language-agnostic rewrites are out of this corpus.
