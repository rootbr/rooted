# Research note — Concepts the tooling reviewer found uncovered

Topic `gaps-tooling` of group H. Tools and hygiene, domain `tooling`, id prefix `TOOL`. Formulation locators: the taxonomy topics of the concepts and their canon locators: internationalization-and-text-encoding (SW4.8).

This gap topic holds three concepts the tooling reviewer found with no card. Each one yields a card, and none repeats or narrows an existing title. TOOL-43 covers recorded moments and TOOL-44 future wall-clock events; the new floating-date card is the third side of that split. No dependency card names CI actions, base images or fetched scripts. (1) Floating dates: the canon does not formulate this. SWEBOK V3 ch. 3 §4.8, opened in place of V4.0, frames only string and character-set handling. The W3C time-zone Editor's Draft states the rule as a SHOULD: holidays, birth dates and anniversaries go in a floating type, and deserializing one into an instant type ties it to UTC. java.time, .NET DateOnly, Temporal, Joda-Time's deprecated DateMidnight, Go civil and Error Prone JavaUtilDate document the type side. MDN and a local run show the failure: a date-only value fixed at UTC midnight reads back as the previous day west of UTC. The 'always aware / store UTC' position contests the rule. It is held by Ruff DTZ001/DTZ011, which Ruff later dropped from its defaults after the CPython datetime maintainer objected, by Effective Python and by the HTML Standard's midnight-UTC valueAsDate. Whether the value names a moment separates the two sides. W3C allows an explicit UTC unfloating for a comparison, and Noda Time tolerates a UTC carrier that is never treated as an instant. No empirical study isolates the defect. (2) Invisible and bidirectional characters: Trojan Source (USENIX Security 2023, arXiv:2111.00169) gives working attacks in twelve languages and the defense of banning the characters and writing escapes. rustc (Deny), Error Prone (ERROR, not disableable), clippy, Pylint, Ruff, ESLint, Semgrep and the Google style guides state the check, and most give the escape fix. The scope is contested. The paper also calls a ban on unterminated controls only the better defense, and GCC's default and clang-tidy take that side. Its GitHub scan found 98.8% of unterminated hits benign. The sources separate the cases by where the character sits. In code and literals an escape keeps the value, so every raw control is replaced. In comments an escape cannot render right-to-left text, and a terminated control cannot distort code outside the comment. PEP 672 and the Java team place enforcement in editors, review tools and project policy, which is where a review card sits. (3) Pinning: its taxonomy home is build-warnings-static-analysis-ci. SEG ch. 18 (hash manifests for third-party artifacts) and SWEBOK V3 SCM §6.1 formulate it. Scorecard, GitHub Docs, Docker Docs, CNCF, zizmor and Semgrep state the SHA, digest or checksum rule. The tj-actions advisory (CVE-2025-30066) records moved tags, and Koishybayev et al. (USENIX Security 2022) measured that 1% of third-party action references use a hash. The industry disagrees on five points: GitHub's trusted-creator exception and major-tag guidance, GitHub's public-preview workflow lockfile that replaces in-file pins, hadolint's release-tag floor for images, the update cost of pins (Scorecard, Docker, He et al. FSE 2025 for npm), and SLSA leaving pinning out of current levels. The sources resolve these by scope (publishers outside the repository's organization and GitHub's actions/ and github/), by accepting a lockfile entry, and by update tooling for staleness. Transitive references and impostor commits remain limits.

## Formulation layer

The canon these locators name formulates none of the three concepts directly. SWEBOK V3 §4.8 (the SW4.8 locator), the 97 Things essays and the aposd-vs-clean-code discussion say nothing about dates that name no moment or invisible characters in source. Concept 3 is the exception: SEG ch. 18 (hash manifests for third-party artifacts, external files that change without a source change) and SWEBOK V3 SCM §6.1 formulate it. SEG18 is a locator of build-warnings-static-analysis-ci, so that topic is concept 3's likely taxonomy home; the candidate names none. Concept 1 is stated as a rule only by the W3C time-zone note, the java.time package docs ("a birthday should be stored in a code LocalDate"), .NET DateOnly and Temporal. MDN shows how it fails: a date-only string parses as UTC midnight. The W3C note also limits the 'never converted' wording: when a floating value must be compared with instants it says to use UTC, and .NET treats a 'Date of birth' that carries a clock time as a moment. Concept 2 rests on Trojan Source §7.6, the Rust advisory and the Google Java/TS/C++ guides. They disagree on scope: the paper calls banning only unterminated controls the 'better' defense and GCC defaults to unpaired, while Rust denies all nine and the Java guide also bans tabs. PEP 672 rejects language-level bans in favour of editors, review tools and project policy. Concept 3 is formulated by Scorecard, GitHub, Docker, CNCF, OWASP and the Go blog, and the sources give it four separating conditions: a trusted creator (GitHub, zizmor), a workflow lockfile that supersedes in-file SHA pins (GitHub, public preview), immutable-release tags, and update tooling that offsets staleness. Pinning is contested by SEG16/SEG21 ('at head' for internal dependencies) and is absent from current SLSA levels, and hadolint asks only for a tag. Not opened: SWEBOK V4 §4.8, RFC 5545, UTS #55, the Noda Time guide, Skeet's essay, the Effective Python text and BSRS ch. 14. WebSearch was not used (budget spent).

## Reception layer

The reception layer covers all three concepts. Most sources are GitHub-hosted files fetched with curl. The bodies of five GitHub issue threads came back verbatim from the GitHub search API and are marked relayed. WebSearch was out of budget, so I could not open Hacker News or Lobsters threads, Jon Skeet's and Paul Ganssle's blogs, the Palo Alto, Chainguard or Wiz posts, Unicode UTS #55 or the PostgreSQL wiki; they appear only as unfetched or relayed items.

**Floating dates.** The rule has support from java.time, Joda-Time (DateMidnight is deprecated for exactly this reason), .NET DateOnly, kotlinx-datetime, Go's civil package and Temporal (now shipping in Chrome 144, Firefox 139 and Node 26). It is contested on two fronts. First, 'always aware' lints (Ruff DTZ001/DTZ011) push the opposite way; CPython datetime maintainer Paul Ganssle called them 'extremely misguided', and Ruff took them out of its defaults. Second, the HTML Standard itself carries a date as a midnight-UTC Date, and the Noda Time guide accepts a UTC carrier as long as every reader treats the value as local. One correction to the candidate evidence: the 'floating time type' advice is in the W3C note, not in dotnet/docs globalization.md. That .NET page instead treats a birth date that includes a time of day as a moment.

**Bidi and invisible characters.** Every tool's fix is the same: replace the raw character with an escape. Tools split on scope. rustc and Error Prone reject any bidi control. GCC's default and clang-tidy flag only unterminated sequences, which the Trojan Source paper itself calls 'a better defense'; its own regex scan found 98.8% false positives. The Java team and PEP 672 hold that editors and project policies should solve it, not the language. Checkstyle's default even flags escapes for control characters.

**Pinning.** Here the canon disagrees most:
- Scorecard, zizmor (since v1.20), Renovate and Docker's docs want a commit SHA or digest.
- GitHub's own actions/toolkit guidance recommends major-version tags.
- GitHub's docs, Semgrep and GHD041 accept tags for trusted first-party actions.
- hadolint and Checkov accept a release tag for images.
- GitHub's 2026 workflow lockfile (public preview) says SHA pinning in workflow files is 'no longer necessary'. Scorecard still flags lock-enforced references as unpinned (ossf/scorecard#5207).

Openable incident records (the tj-actions and reviewdog GHSAs) show both what a moved tag costs and where SHA pinning stops working: a composite action that pulls another action by a mutable tag.

## Evidence layer

Floating dates: the W3C time-zone Editor's Draft states the rule as a SHOULD. It says to use a floating type for holidays, birth dates and anniversaries, and that deserializing a floating value into an incremental type ties it to UTC. .NET DateOnly, java.time LocalDate and LocalTime, Temporal PlainDate and PlainTime, Go civil and Error Prone JavaUtilDate document the type side. MDN documents the date-only-parsed-as-UTC mechanism, and a local run reproduced the one-day shift in JS, Java and Python. No empirical study isolates this defect; the MSR 2025 date-time bug dataset holds one adjacent instance. Two limits apply: .NET treats a date of birth that carries a clock time as a moment, and W3C advises unfloating with UTC when a floating value must be compared with instants. Invisible and bidi characters: rustc (Deny), Error Prone (ERROR, not disableable), clippy, Pylint, Ruff, ESLint, Semgrep and the Google Java and C++ style guides state the check, and most give the escape remedy. The Trojan Source paper (USENIX Security 2023, opened as a GitHub-hosted PDF) gives the ban and the escape remedy. It also proposes a narrower ban on unterminated controls only, after a GitHub-wide scan returned 98.8% false positives. In a local run, Go 1.24 and Python 3.13 accepted the attack silently, GCC 13 only warned, and UTS #55 could not be opened. Pinning: OpenSSF Scorecard, GitHub Docs, Docker Docs, zizmor and Semgrep state the SHA or digest rule. The tj-actions advisory (CVE-2025-30066) records tags moved to point at a malicious commit, and Koishybayev et al. measured that only 1% of third-party action references use a commit hash. The rule is contested by GitHub's trusted-creator exception, by its public-preview workflow lockfile that replaces in-file SHA pins, by hadolint accepting release tags, by OWASP CICD-SEC-3 accepting version ranges, and by He et al. (FSE 2025) on npm version pinning. Papers were reached only through GitHub-hosted copies; arXiv, USENIX, unicode.org and the vendor sites were not opened, and WebSearch was exhausted.

1. **A calendar date or wall-clock time that names no moment, such as a birth date, a holiday, an anniversary or an opening time, is held, stored and serialized in a local date or time type with no offset or zone, never as an instant at midnight in UTC or in the host's zone** — A date or time value that is not tied to a specific offset or time zone rules, a calendar date such as a birth date, a holiday or an anniversary or a wall-clock time such as an opening time, is held in the language's floating type (a local or plain date, time or date-time) and stored and serialized without an offset or zone identifier, never typed, stored or exchanged as an instant fixed at midnight in UTC or in the host's zone. Deserializing such a value into an instant type ties it to UTC, and a date held in a date-time can roll into the previous or next day once a zone offset is applied, so it shows as another date to users in other zones.
